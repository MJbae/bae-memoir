# 내 논을 파는 한이 있어도

『내 논을 파는 한이 있어도』, 배병희 자전소설을 가족이 휴대폰으로 읽는 서재입니다. 정본 [배병희_자서전.md](배병희_자서전.md)를 프롤로그, 6부 23화, 에필로그, 외전으로 엮었습니다. [웹소설형 연재 개편 제안서](웹소설형_연재_개편_제안서.md)의 **1단계 원고 재배치와 서비스 개편**을 적용했습니다. 인물 인터뷰와 가족의 기억을 바탕으로 회당 4,000~5,000자로 확장하는 2단계 소설화는 다음 작업입니다.

작품 홈은 작품명을 모바일 36px·데스크톱 44px의 두 줄 제목으로 보여주고 작품 정보 바로 아래에 처음부터 읽기·이어서 읽기·다음 화 읽기를 둡니다. 소개글 뒤에는 6개 부의 바로가기와 짧은 설명이 있는 회차 목록이 이어집니다. 읽던 화에는 배경과 표시선을, 읽은 화에는 체크 표시를 붙입니다. 같은 브라우저에서 읽던 위치와 읽은 회차를 기억하며 마지막 회차를 마치면 처음부터 다시 읽기를 제공합니다. 회차 화면 상단에는 목록과 보기 설정만 둡니다. 본문 글자는 18·20·23·26px 가운데 고를 수 있고 기본은 20px, 행간은 1.85입니다. 주요 조작은 16px, 보조 정보는 14px을 기준으로 맞췄습니다. 큰 글씨 단계에서는 댓글과 입력창도 23·26px로 커지고 주요 조작은 18px로 커집니다. 화면은 기기 설정을 따르며 자동·밝게·어둡게를 직접 고를 수 있습니다.

회차 끝은 반응 → 다음 화 읽기 → 이전 화 → 댓글 순서입니다. 다음 화 버튼은 행동과 회차 제목을 두 줄로 구분합니다. 첫 회차에는 이전 화 영역이 없고, 마지막 회차에는 전체 회차 보기 버튼을 표시합니다. 중복되는 우측 하단 목록 링크는 표시하지 않습니다. 회원가입 없이 읽고 이름만 적어 댓글을 남깁니다. Firebase를 연결하지 않으면 반응·댓글 영역을 숨기고 정적 읽기를 제공합니다. 검색·필터·예상 읽기 시간·진행률·별점·하단 도구 모음은 표시하지 않습니다.

## 로컬 실행과 검증

Node.js 22 이상을 사용합니다.

```sh
npm ci
npm run dev
```

기본 주소는 `http://127.0.0.1:5173/bae-memoir/`입니다. 원고를 수정했을 때는 개발 서버를 다시 시작하거나 `npm run prepare:content`를 실행하세요. 생성되는 `site/read/`와 `site/.vitepress/generated/`는 직접 편집하거나 커밋하지 않습니다.

```sh
npm test
npm run build
npm run typecheck
npm run test:sharing
npx playwright install chromium
npm run test:e2e
```

콘텐츠 검사는 회차 본문 보존, 자동 번호, ID·부·시점 검증, 주소와 댓글 ID 유지, 옛 주소 대응, 자료 수집과 링크 변환을 확인합니다. 모바일·320px·데스크톱 검사에서는 회차 이동, 읽음·이어보기, 화면 모드, 큰 글씨, 자바스크립트 없는 옛 주소 이동을 확인합니다.

Firestore 규칙과 반응·댓글의 실제 저장 흐름은 Java 21 이상의 로컬 에뮬레이터에서 검사합니다. 운영 데이터에는 연결하지 않습니다.

```sh
npm run test:rules
npm run test:comments
```

## 정본의 회차 표기

정본은 한 파일로 유지합니다. 제목과 소개글은 frontmatter에서 수정합니다. 소개글은 문단별 배열로 쓰며, 연재 요일을 정한 뒤에만 `schedule` 한 줄을 추가합니다.

```md
---
title: 내 논을 파는 한이 있어도
subtitle: 배병희 자전소설
synopsis:
  - "거래처는 3억 원의 쌀값을 치르지 못한 채 사라졌다. …"
  - "안면도 갯벌에서 지게를 지던 막내가 …"
---

## 프롤로그. 벼 한 톨의 무게 {#prologue}

*1990년대 초, 화성 독정리*

본문을 적습니다.

# 1부. 갯벌

## 어머니의 조새 {#josae}

*어린 시절(1936년 출생) · 안면도 중장리*

본문을 적습니다.

* * *

다음 장면을 적습니다.
```

- 부는 `# N부. 이름`으로 적고 번호는 1부터 차례로 지정합니다.
- 본편은 `## 제목 {#id}`로 적습니다. 원고 순서로 1화부터 자동 번호를 붙입니다.
- 프롤로그·에필로그·외전은 `## 프롤로그. 제목 {#prologue}`, `## 에필로그. 제목 {#epilogue}`, `## 외전. 제목 {#side-table}`로 구분합니다. 외전이 여러 편이면 외전 번호를 따로 붙입니다.
- 회차 ID는 영문 소문자·숫자·하이픈으로 1~40자, 필수이며 중복을 허용하지 않습니다. **공개한 ID는 바꾸지 않습니다.** 제목·순서·부가 바뀌어도 주소와 댓글은 ID를 따릅니다. `prologue`·`epilogue`는 예약 ID입니다.
- 회차 첫 줄에는 40자 이내의 `*때, 곳*`을 적습니다. 목록과 회차 머리에 표시합니다.
- 회차 안에는 소제목을 넣지 않고 `* * *`로 장면을 나눕니다. `###`는 본문을 보존하되 빌드 경고를 냅니다.
- 본편은 에필로그와 외전 앞에 둡니다. 부 제목 아래에 회차 바깥의 본문을 쓰면 빌드가 중단됩니다.

이번 재배치의 원본과 문단 대응표는 `_workspace/2026-10-06-restructure/`에 있습니다. 이주 연도는 ‘1977년 무렵’, 전쟁과 보리 타작은 ‘6·25 전쟁 무렵’, 혼인은 ‘스물다섯 살’로 유지했습니다. 회전 벨트 사건의 ‘안면도 시절’이라는 원문도 유지하며 11화에서 지난날의 기억으로 안내합니다. 군번의 열두 자리는 기존 원고를 따르며 추가 확인 대상입니다.

## 추가 자료

새 글은 저장소 루트나 `content/**/*.md`에 넣습니다. 숨김 파일·폴더, 심볼릭 링크, 운영·개발 문서, 편집 제안서는 수집하지 않습니다. 제안서 제외는 정확한 파일명에만 적용하며 일반 가족 자료는 계속 게시합니다. `published: false`나 `draft: true`는 사이트에서만 숨깁니다. 공개 저장소에 커밋한 파일 자체는 GitHub에서 공개됩니다.

```md
---
id: moving-day
title: 독정리로 이사하던 날
category: 가족의 기억
date: 1977-04-01
---

# 독정리로 이사하던 날

기억을 적습니다.
```

추가 자료의 `id`는 영문 소문자·숫자·하이픈·밑줄로 1~80자이며 고정해서 사용하는 것을 권합니다. 생략하면 파일 경로에서 생성하므로 파일명이나 위치가 바뀔 때 댓글 연결도 달라집니다. `title`·`description`·`category`·`date`는 선택 항목입니다. Markdown의 상대 사진·첨부파일·공개 자료 링크를 변환하며 임의 HTML이나 스크립트는 실행하지 않습니다.

## Firebase 최초 연결과 배포

1. [Firebase 콘솔](https://console.firebase.google.com/)에서 Spark 요금제의 프로젝트를 만듭니다.
2. Authentication의 Anonymous(익명) 로그인을 활성화합니다. 독자는 반응·하트·댓글을 처음 저장할 때만 자동 익명 로그인합니다. 읽기만 해서는 계정을 만들지 않습니다.
3. Firestore Standard edition의 `(default)` 데이터베이스를 Production mode로 만듭니다. 한국 가족 중심이라면 제공되는 서울 지역을 선택할 수 있습니다.
4. 웹 앱을 등록하고 공개 앱 설정 네 값을 복사합니다. Firebase Hosting 연결은 필요 없습니다.

| Firebase 설정 | 환경변수 |
| --- | --- |
| apiKey | `VITE_FIREBASE_API_KEY` |
| authDomain | `VITE_FIREBASE_AUTH_DOMAIN` |
| projectId | `VITE_FIREBASE_PROJECT_ID` |
| appId | `VITE_FIREBASE_APP_ID` |

로컬에서는 `.env.example`을 `.env`로 복사해 값을 입력합니다. 이 값은 브라우저용 공개 설정이며 서비스 계정 키·Admin SDK 비밀키를 `VITE_` 변수나 저장소에 넣지 않습니다. 읽기 경로의 기본값은 `SITE_BASE=/bae-memoir/`입니다.

```sh
cp .env.example .env
npx firebase login
npx firebase deploy --only firestore:rules,firestore:indexes --project YOUR_PROJECT_ID
```

**규칙을 먼저 배포하고 사이트를 배포합니다.** 이 Firebase는 기존 `autobio-bae` 사이트와 공유합니다. 이 저장소의 규칙은 접두어 없는 기존 댓글 규칙도 유지합니다. 다른 저장소의 옛 규칙을 다시 배포하면 새 반응·하트 규칙이 사라질 수 있으므로 이 저장소를 정본으로 사용합니다.

GitHub 저장소의 Settings → Secrets and variables → Actions → Variables에 네 값을 넣고, Settings → Pages의 Source를 GitHub Actions로 선택합니다. `main`에 푸시하면 테스트·빌드·공유 정보·타입 검사를 통과한 결과가 자동 배포됩니다. PR에서는 검증만 합니다. 환경변수 변경 후에는 Pages 워크플로를 다시 실행합니다. 사이트 주소는 `https://mjbae.github.io/bae-memoir/`이며 워크플로가 저장소명에서 `SITE_BASE`를 지정합니다.

## 반응·댓글 운영

회차 반응은 ❤️ 응원해요·👍 좋아요·😢 뭉클해요·👏 대단해요 네 가지입니다. 한 익명 사용자당 하나만 선택하며 다른 반응으로 변경하거나 같은 반응을 눌러 취소합니다. 빠른 연속 입력은 마지막 상태로 묶어 저장하고 서버는 1초 간격을 검사합니다. 375px 미만에서는 네 반응을 2×2로 배치하고, 숫자가 없는 반응도 숫자 자리의 높이를 확보해 버튼 위치를 유지합니다. 기존 `remember` 필드는 배포된 규칙·색인과의 호환성을 위해 저장 형식에만 남기며 새 반응을 저장할 때 0으로 초기화합니다. 해당 반응과 연결 안내는 화면에 표시하지 않습니다. 숫자는 1 이상일 때만 표시합니다.

댓글 입력창은 처음에는 접어 두고 누르면 이름·내용·남기기가 펼쳐집니다. 이름은 24자, 내용은 2,000자 이내이며 등록 간격은 15초입니다. 30개씩 불러오고 상시 실시간 구독을 사용하지 않습니다. 댓글 제목의 숫자는 불러온 수이며 30개 이상에서 더 불러올 댓글이 있거나 30개를 넘겨 읽었으면 `30+`로 표시합니다. 새 댓글은 페이지 새로고침으로 확인합니다.

한 단계 답글과 같은 브라우저의 본인 수정·삭제를 지원합니다. 부모 댓글을 삭제해도 다른 사람의 답글은 남고 답글 작성자는 계속 수정·삭제할 수 있습니다. 소유권은 이름이 아니라 익명 UID로 판단합니다. 브라우저 데이터를 지우거나 기기·도메인을 바꾸면 작성 권한을 이어받지 못합니다. 익명 계정 자동 삭제는 켜지 않습니다.

댓글과 답글에는 ‘공감해요’로 반응을 남기고 다시 눌러 취소할 수 있습니다. 자기 댓글에는 수만 표시합니다. 저장소의 기존 하트 문서와 댓글의 `heartCount`를 유지해 배치로 함께 변경하며 규칙이 두 변경을 대조합니다. 중복 하트, 자기 댓글 하트, 숫자만 바꾸는 요청은 거절합니다. 댓글 삭제 뒤에 남은 하트 문서는 화면에 쓰이지 않습니다.

본문, 이름과 댓글, 반응 수는 공개됩니다. 가족 초대나 신원 확인 기능은 없으며 익명 세션을 새로 만들어 수를 부풀리는 행위까지 막지는 않습니다. 베스트 댓글·이메일 알림은 없습니다.

| 데이터 | 저장 위치 |
| --- | --- |
| 본편·외전 댓글 | `pages/memoir-ep-{id}/comments/{commentId}` |
| 프롤로그·에필로그 댓글 | `pages/memoir-life-prologue/comments`, `pages/memoir-life-epilogue/comments` |
| 회차 반응 | 해당 페이지의 `reactions/{uid}` |
| 댓글 하트 | 해당 댓글의 `hearts/{uid}` |
| 추가 자료 댓글 | `pages/memoir-{자료 ID}/comments` |
| 기존 사이트 댓글 | 접두어 없는 `pages/{기존 ID}/comments` — 별개로 유지 |

배포 전에 Firebase 콘솔에서 이 사이트의 옛 `memoir-life-1930s` 등 연대 댓글을 확인하세요. 0건이면 데이터 이전이 필요 없습니다. 있다면 내용을 읽고 해당 회차로 옮기되 댓글 ID·uid·작성 시각·parentId를 유지하고 답글은 부모와 같은 회차로 옮깁니다. 프롤로그·에필로그와 접두어 없는 기존 사이트의 댓글은 옮기지 않습니다. 2026년 10월 6일 배포 전 확인에서 이 사이트의 옛 연대별 댓글은 모두 0건이어서 데이터 이전이 필요하지 않았습니다. 반응·댓글 하트 규칙을 운영 Firebase에 먼저 배포했습니다.

반응 집계에는 `firestore.indexes.json`에 정의한 `reactions` 복합 색인이 필요합니다. 규칙과 색인을 먼저 배포하고 색인 생성이 완료된 뒤 사이트를 배포합니다. 반응은 기존 색인과의 호환성을 유지하는 서버 집계 요청 하나로 합계를 받아 네 가지 반응만 표시하며, 기존 익명 세션이 있으면 자신의 문서 하나도 읽습니다. 반응·댓글은 회차 끝 350px 앞에서 불러옵니다. 하트는 문서와 수를 합쳐 두 번 씁니다. [Firestore 무료 제공량](https://firebase.google.com/docs/firestore/quotas#free-quota) 안에서 운영하며 사용량은 콘솔에서 확인합니다. 무료 한도를 넘겨 반응·댓글이 제한되어도 정적 본문은 읽을 수 있습니다.

## 공유 이미지

공유 제목에는 작품명과 회차 번호·제목, 설명에는 시점 줄이 들어갑니다. canonical·Open Graph·Twitter 정보는 자바스크립트 없이 HTML에 있습니다. 공유 이미지 `site/public/og-image.png`는 1200×630이며 작품명을 반영했습니다. 아이콘과 모바일 manifest는 같은 폴더에 있습니다.

```sh
npm run assets:share
```

문구를 바꾸려면 `scripts/generate-share-assets.mjs`를 수정하고 Playwright Chromium으로 위 명령을 실행합니다.
