# 내 논을 파는 한이 있어도

『내 논을 파는 한이 있어도』, 배병희 자전소설을 가족이 휴대폰으로 읽는 서재입니다. 정본 [배병희_자서전.md](배병희_자서전.md)를 프롤로그, 6부 23화, 에필로그, 외전으로 엮었습니다. [웹소설형 연재 개편 제안서](웹소설형_연재_개편_제안서.md)의 **1단계 원고 재배치와 서비스 개편**을 적용했습니다. 인물 인터뷰와 가족의 기억을 바탕으로 회당 4,000~5,000자로 확장하는 2단계 소설화는 다음 작업입니다.

작품 홈과 회차 화면에 B안 디자인을 적용했습니다. 홈은 모바일·데스크톱 모두 중앙 단일 열이며, 작품 부제와 톱니바퀴 ‘설정’, 두 줄 제목과 작은 수채화 초상을 보여 줍니다. 완결·부속 회차 안내는 상단에 표시하지 않습니다. 처음 방문하면 소개 전체가 보이고, 읽기 기록이 있으면 모든 소개 문장과 인용문을 접습니다. ‘작품 소개 보기/접기’로 원문 전체를 펼치거나 숨깁니다. 소개 아래, 목차 위에 처음부터 읽기·이어서 읽기·다음 화 읽기 버튼을 둡니다. 목차에는 부별 설명, 읽는 중 또는 최근 본 화, 읽은 회차의 체크가 있습니다. 목차의 읽는 중 회차도 이어 읽기 버튼과 같은 저장 위치로 돌아갑니다.

같은 브라우저에서 읽던 위치와 회차별 읽음 이력을 기억합니다. 현재 진행 중인 읽기와 과거 읽음 이력을 구분해 재독 중에도 이어 읽기가 가능합니다. 마지막 외전만 읽은 경우 아직 읽지 않은 이야기로 연결하며, 전체 회차가 읽음 상태일 때 처음부터 다시 읽기를 제공합니다. 읽음은 회차 끝이 화면에 나타난 기록입니다.

홈과 회차 상단의 ‘설정’에서 배경음악·글자 크기·화면 모드를 조정합니다. 본문 크기는 18·20·23·26px이며, 작게·기본·크게·아주 크게로 표시합니다. 기본 20px, 행간 1.85를 유지하고 설정 안에서 글씨를 미리 볼 수 있습니다. 화면은 기기 설정·밝게·어둡게 가운데 고릅니다. 변경은 즉시 저장하고 ‘설정 마치기’나 X·Escape·바깥 영역으로 닫습니다. 주요 조작은 16px, 보조 정보는 14px이며 큰 글씨 단계에서 함께 커집니다.

첫 화면과 회차 이동은 같은 `ReadingLink`를 사용합니다. 주요 읽기·다음 화는 청회색 단색과 얕은 그림자, 이전 화는 중립적인 옅은 바탕과 테두리를 사용합니다. 회차 이동은 ‘← 이전 화’와 ‘다음 화 →’만 표시하고 두 버튼을 같은 크기·56px 높이·12px 간격·12px 모서리로 나란히 둡니다. 홈 버튼에 회차 정보가 있으면 80px 이상으로 자연스럽게 늘어납니다. 첫 회차는 다음 화 하나, 마지막 회차는 목차 아이콘과 ‘목차’를 표시합니다. 반응의 저장 결과는 눈에 보이는 문구로 안내합니다. Firebase가 없으면 반응을 숨기고 정적 읽기를 제공합니다. 한 번에 읽기·댓글·검색·필터·예상 읽기 시간·진행률·별점·하단 도구 모음은 표시하지 않습니다.

## 로컬 실행과 검증

Node.js 22 이상을 사용합니다.

```sh
npm ci
npm run dev
```

기본 주소는 `http://127.0.0.1:5173/bae-memoir/`입니다. 원고를 수정했을 때는 개발 서버를 다시 시작하거나 `npm run prepare:content`를 실행하세요. 생성되는 `site/read/`와 `site/.vitepress/generated/`는 직접 편집하거나 커밋하지 않습니다.

```sh
npm test
npm run build
npm run typecheck
npm run test:sharing
npx playwright install chromium
npm run test:e2e
```

콘텐츠 검사는 회차 본문 보존, 자동 번호, ID·부·시점 검증, 주소와 문서 ID 유지, 옛 주소 대응, 자료 수집과 링크 변환을 확인합니다. 모바일·320px·데스크톱 검사에서는 소개 전체 접기, 통합 설정·음악 스위치, 회차 이동, 읽음·재독·이어보기, 화면 모드, 큰 글씨, 자바스크립트 없는 옛 주소 이동을 확인합니다.

Firestore 규칙과 반응의 실제 저장 흐름은 Java 21 이상의 로컬 에뮬레이터에서 검사합니다. Firebase가 연결된 화면에서도 댓글이 표시되지 않는지 확인하며 운영 데이터에는 연결하지 않습니다.

```sh
npm run test:rules
npm run test:reactions
```

## 정본의 회차 표기

정본은 한 파일로 유지합니다. 제목과 소개글은 frontmatter에서 수정합니다. 소개글은 문단별 배열로 쓰며, 연재 요일을 정한 뒤에만 `schedule` 한 줄을 추가합니다.

```md
---
title: 내 논을 파는 한이 있어도
subtitle: 배병희 자전소설
synopsis:
  - "거래처는 3억 원의 쌀값을 치르지 못한 채 사라졌다. …"
  - "안면도 갯벌에서 지게를 지던 막내가 …"
---

## 프롤로그. 벼 한 톨의 무게 {#prologue}

*1990년대 초, 화성 독정리*

본문을 적습니다.

# 1부. 갯벌

## 어머니의 조새 {#josae}

*어린 시절(1936년 출생) · 안면도 중장리*

본문을 적습니다.

* * *

다음 장면을 적습니다.
```

- 부는 `# N부. 이름`으로 적고 번호는 1부터 차례로 지정합니다.
- 본편은 `## 제목 {#id}`로 적습니다. 원고 순서로 1화부터 자동 번호를 붙입니다.
- 프롤로그·에필로그·외전은 `## 프롤로그. 제목 {#prologue}`, `## 에필로그. 제목 {#epilogue}`, `## 외전. 제목 {#side-table}`로 구분합니다. 외전이 여러 편이면 외전 번호를 따로 붙입니다.
- 회차 ID는 영문 소문자·숫자·하이픈으로 1~40자, 필수이며 중복을 허용하지 않습니다. **공개한 ID는 바꾸지 않습니다.** 제목·순서·부가 바뀌어도 주소와 반응·읽기 기록은 ID를 따릅니다. `prologue`·`epilogue`는 예약 ID입니다.
- 회차 첫 줄에는 40자 이내의 `*때, 곳*`을 적습니다. 목록과 회차 머리에 표시합니다.
- 회차 안에는 소제목을 넣지 않고 `* * *`로 장면을 나눕니다. `###`는 본문을 보존하되 빌드 경고를 냅니다.
- 본편은 에필로그와 외전 앞에 둡니다. 부 제목 아래에 회차 바깥의 본문을 쓰면 빌드가 중단됩니다.

이번 재배치의 원본과 문단 대응표는 `_workspace/2026-10-06-restructure/`에 있습니다. 이주 연도는 ‘1977년 무렵’, 전쟁과 보리 타작은 ‘6·25 전쟁 무렵’, 혼인은 ‘스물다섯 살’로 유지했습니다. 회전 벨트 사건의 ‘안면도 시절’이라는 원문도 유지하며 11화에서 지난날의 기억으로 안내합니다. 군번의 열두 자리는 기존 원고를 따르며 추가 확인 대상입니다.

## 추가 자료

새 글은 저장소 루트나 `content/**/*.md`에 넣습니다. 숨김 파일·폴더, 심볼릭 링크, 운영·개발 문서, 편집 제안서는 수집하지 않습니다. 제안서 제외는 정확한 파일명에만 적용하며 일반 가족 자료는 계속 게시합니다. `published: false`나 `draft: true`는 사이트에서만 숨깁니다. 공개 저장소에 커밋한 파일 자체는 GitHub에서 공개됩니다.

```md
---
id: moving-day
title: 독정리로 이사하던 날
category: 가족의 기억
date: 1977-04-01
---

# 독정리로 이사하던 날

기억을 적습니다.
```

추가 자료의 `id`는 영문 소문자·숫자·하이픈·밑줄로 1~80자이며 고정해서 사용하는 것을 권합니다. 생략하면 파일 경로에서 생성하므로 파일명이나 위치가 바뀔 때 게시 주소도 달라집니다. `title`·`description`·`category`·`date`는 선택 항목입니다. Markdown의 상대 사진·첨부파일·공개 자료 링크를 변환하며 임의 HTML이나 스크립트는 실행하지 않습니다.

## Firebase 최초 연결과 배포

1. [Firebase 콘솔](https://console.firebase.google.com/)에서 Spark 요금제의 프로젝트를 만듭니다.
2. Authentication의 Anonymous(익명) 로그인을 활성화합니다. 독자는 반응을 처음 저장할 때만 자동 익명 로그인합니다. 읽기만 해서는 계정을 만들지 않습니다.
3. Firestore Standard edition의 `(default)` 데이터베이스를 Production mode로 만듭니다. 한국 가족 중심이라면 제공되는 서울 지역을 선택할 수 있습니다.
4. 웹 앱을 등록하고 공개 앱 설정 네 값을 복사합니다. Firebase Hosting 연결은 필요 없습니다.

| Firebase 설정 | 환경변수 |
| --- | --- |
| apiKey | `VITE_FIREBASE_API_KEY` |
| authDomain | `VITE_FIREBASE_AUTH_DOMAIN` |
| projectId | `VITE_FIREBASE_PROJECT_ID` |
| appId | `VITE_FIREBASE_APP_ID` |

로컬에서는 `.env.example`을 `.env`로 복사해 값을 입력합니다. 이 값은 브라우저용 공개 설정이며 서비스 계정 키·Admin SDK 비밀키를 `VITE_` 변수나 저장소에 넣지 않습니다. 읽기 경로의 기본값은 `SITE_BASE=/bae-memoir/`입니다.

```sh
cp .env.example .env
npx firebase login
npx firebase deploy --only firestore:rules,firestore:indexes --project YOUR_PROJECT_ID
```

**규칙을 먼저 배포하고 사이트를 배포합니다.** 이 Firebase는 기존 `autobio-bae` 사이트와 공유합니다. 이 저장소의 규칙은 접두어 없는 기존 댓글 규칙도 유지합니다. 다른 저장소의 옛 규칙을 다시 배포하면 현재 반응 규칙이 사라질 수 있으므로 이 저장소를 정본으로 사용합니다.

GitHub 저장소의 Settings → Secrets and variables → Actions → Variables에 네 값을 넣고, Settings → Pages의 Source를 GitHub Actions로 선택합니다. `main`에 푸시하면 테스트·빌드·공유 정보·타입 검사를 통과한 결과가 자동 배포됩니다. PR에서는 검증만 합니다. 환경변수 변경 후에는 Pages 워크플로를 다시 실행합니다. 사이트 주소는 `https://mjbae.github.io/bae-memoir/`이며 워크플로가 저장소명에서 `SITE_BASE`를 지정합니다.

## 반응 운영

회차 반응은 ❤️ 응원해요·👍 좋아요·😢 뭉클해요·👏 대단해요 네 가지입니다. 한 익명 사용자당 하나만 선택하며 다른 반응으로 변경하거나 같은 반응을 눌러 취소합니다. 빠른 연속 입력은 마지막 상태로 묶어 저장하고 서버는 1초 간격을 검사합니다. 375px 미만에서는 네 반응을 2×2로 배치하고, 숫자가 없는 반응도 숫자 자리의 높이를 확보해 버튼 위치를 유지합니다. 기존 `remember` 필드는 배포된 규칙·색인과의 호환성을 위해 저장 형식에만 남기며 새 반응을 저장할 때 0으로 초기화합니다. 해당 반응과 연결 안내는 화면에 표시하지 않습니다. 숫자는 1 이상일 때만 표시합니다.

반응은 `pages/memoir-ep-{id}/reactions/{uid}`에 저장합니다. 프롤로그·에필로그는 각각 `memoir-life-prologue`, `memoir-life-epilogue`를 사용합니다. 기존 익명 로그인과 회차 ID를 유지해 저장된 반응을 계속 불러옵니다. 댓글 UI·작성·조회·수정·삭제·답글·공감 코드는 제거했습니다. 공유 Firebase를 사용하는 기존 사이트와 저장된 데이터에 필요한 댓글 규칙·색인은 유지합니다.

반응 집계에는 `firestore.indexes.json`에 정의한 `reactions` 복합 색인이 필요합니다. 규칙과 색인을 먼저 배포하고 색인 생성이 완료된 뒤 사이트를 배포합니다. 반응은 기존 색인과의 호환성을 유지하는 서버 집계 요청 하나로 합계를 받아 네 가지 반응만 표시하며, 기존 익명 세션이 있으면 자신의 문서 하나도 읽습니다. 반응은 회차 끝 350px 앞에서 불러옵니다. 읽기만 해서는 익명 계정을 만들지 않습니다. 무료 한도를 넘겨 반응이 제한되어도 정적 본문은 읽을 수 있습니다.

## 배경 음악

`site/public/music/`의 27곡을 홈과 각 회차에 연결해 반복 재생합니다. 기본 켜짐과 3% 고정 음량을 유지하며, 별도 재생 아이콘은 홈·회차 도구에 노출하지 않습니다. ‘설정’ 안의 배경음악 스위치로 켜고 끄며 재생 선택을 같은 브라우저에서 기억합니다. 꺼진 상태로 페이지를 이동하면 곡을 내려받지 않습니다. 같은 곡을 껐다 켜면 일시정지한 위치에서 이어집니다. 자동재생이 막히면 기존처럼 첫 조작에서 시작을 시도하며 설정 안에 재생 행동을 제공합니다. 준비·재생·차단·오류 상태를 안내하고 음악 불러오기 실패 시 다시 재생할 수 있습니다. 회차 이동 시 하나의 재생기가 해당 곡으로 전환합니다.

곡 연결은 `content/music.json`에서 관리하며, 파일명과 연결 모두 공개 회차 ID를 기준으로 유지합니다. 회차의 제목·순서를 바꾸어도 곡은 해당 회차를 따릅니다. 파일 누락, 중복 연결, 미등록 MP3, 음악 없는 회차는 빌드에서 알려줍니다. 원래 파일명과 변경한 파일명, 원본 SHA-256은 `_workspace/2026-10-06-music/file-map.json`에 보관합니다. 음악 파일의 내용은 변경하지 않았습니다.

## 회차 삽화

프롤로그·본편 23화·에필로그·외전의 26개 회차에 수채화 삽화 30장을 배치했습니다. 약 1,000자 이상의 회차 중 서로 다른 장면이 이어지는 9·14·21·22화에는 2장, 나머지에는 1장을 사용합니다. 메인 초상과 같은 투명 수채화·종이 질감·황토색과 청회색을 기준으로 `content/ref_images/`의 실제 인물·장소·도구 사진을 참고해 내장 `image_gen`으로 제작했습니다. 젊은 시절과 옛 정미소는 원고의 시대에 맞춘 재구성 삽화입니다.

배치 목록은 `content/episode-illustrations.json`, 서비스용 파일은 `site/public/images/episodes/`에 있습니다. 모든 그림은 가로 16:9이며 360·720·1280px 파일을 화면 크기에 따라 불러옵니다. WebP를 우선 사용하고 JPG도 호환용으로 제공합니다. 첫 그림은 바로 불러오고 뒤의 그림은 해당 장면이 가까워지면 불러옵니다. 그림을 잘라내지 않고 전체 구도를 표시하며 대체 설명과 크기를 제공합니다. 원고를 편집하지 않고 Markdown 렌더링 단계에서 삽화만 추가하므로 개별 회차에 지정한 그림이 표시됩니다. 배치 문단이 바뀌거나 이미지 파일이 빠지면 빌드에서 알려줍니다.

선정한 사진·장면·배치 이유·제작 프롬프트는 `_workspace/2026-10-06-episode-images/plan.json`, 생성 기록은 같은 폴더의 `results.json`, 원본 PNG는 `originals/`에 보관합니다. 본문을 수정해도 회차 ID가 같으면 첫 그림은 유지됩니다. 두 번째 그림의 위치를 바꾸려면 목록의 `position.beforeParagraph`를 원고의 해당 문단 전체로 수정하세요. 서비스용 WebP·JPG의 재생성은 `node _workspace/2026-10-06-episode-images/prepare-assets.mjs`로 실행합니다.

## 공유 이미지

공유 제목에는 작품명과 회차 번호·제목이 들어갑니다. 홈의 공유 설명은 ‘배병희 자전소설 · 갯벌에서 들녘까지, 가족과 이웃을 위해 살아온 한평생.’을 사용하고, 회차의 공유 설명에는 시점 줄이 들어갑니다. 첫 화면의 작품 부제와 소개글은 정본의 `subtitle`과 `synopsis`를 그대로 표시합니다. canonical·Open Graph·Twitter 정보는 자바스크립트 없이 HTML에 있습니다. 홈과 모든 회차의 공유 이미지는 `site/public/images/bae-byunghee-hero-watercolor.png`에 있는 배병희의 수채화 초상 원본(1672×941)을 사용합니다. 이미지 주소는 사이트 경로를 포함한 HTTPS 절대 주소이며, 실제 크기와 대체 설명을 메타데이터에 함께 제공합니다. 아이콘과 모바일 manifest는 `site/public/`에 있습니다.

```sh
npm run assets:share
```

위 명령은 Playwright Chromium으로 아이콘과 모바일 manifest를 다시 생성합니다. 공유 이미지는 기존 수채화 원본을 그대로 사용합니다. 이미지를 교체할 때는 `site/.vitepress/config.mts`의 경로·크기·대체 설명도 함께 수정하세요.
